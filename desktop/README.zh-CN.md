# Tallnum 计算器（Windows x64）

## 界面语言

侧栏的“Language / 语言”可在简体中文和英文间即时切换，选择保存在当前应用配置的本地存储中。计算器、任务与结果对比、结构规划、概率表规划和自动玩共用语言设置；显示标题、提示、按钮、表头、状态及已知错误会随之变化。用户输入、任务文件、路径、原始日志和代码/JSON显示保持原始内容，语言设置不影响模型或计算结果。旧安装副本需重新构建或打包才能获得此功能。

本地化回归：`node desktop/scripts/test-localization.cjs`。根目录[英文使用指南](../README.md)和[中文使用指南](../README.zh-CN.md)介绍各模块的完整流程。

开发版新增「自动玩」页：五格定式统计、目标 768 拆解规划、完整模拟验证和真实网页控制。此功能另需 Python、SciPy；当前实机游玩通过 CDP 连接已有的 Chrome 标签页。测试浏览器另需 Playwright。使用与计算说明见 [自动化说明](../automation/README.zh-CN.md)。现有计算器功能的依赖不变。

## 安装与使用

当前源码的定式计算器采用概率表值迭代，输出两枚可见待出数的 36 种状态成功概率。`release-0.4.0/Tallnum-Calculator-0.4.0-win-x64.exe` 是此前固定策略表版本的安装包，尚未包含本次源码修改。计算数据保存在新建任务时选择的目录，每个任务独立占一个子目录。

1. 在「新建计算」填写空格数、目标、最终占格上限和允许的基。定式至少五格，目标至少24；五格目标64上限仅属于十格10240低阶路线约定。
2. 设置概率表值迭代的轮数和收敛阈值。可串联多个值迭代阶段；最终阶段未达到阈值时，任务不会标为完成。
3. 创建任务后在「任务」查看每阶段按第一、第二枚待出数排列的 6×6 成功概率表、迭代轮数、残差和日志。多个任务串行运行。
4. 使用「暂停」「继续」「取消」控制任务。关闭窗口会收起到托盘；托盘「保存并退出」会等待当前计算保存检查点后退出。
5. 在「结果对比」逐个待出数状态比较两个阶段。JSON 和 CSV 导出均列出阶段、两枚待出数和对应成功概率。

值迭代计算状态成功概率，并在每个状态选取成功概率最大的动作。初始盘面的 36 个值来自同一概率表；程序核对它们的平均值与求解器汇总值一致。旧固定策略表任务保留历史记录，但不能继续计算或作为新任务导出。

默认规则：5 个空格，目标 48，目标组合最多占 5 格，基为 1、3、5、15，成功块紧邻 F 上方；发牌固定为 2、4、6、8、10、15，各占 1/6。基列表不改变发牌。普通目标块算成功，中间组合最多占 5 格。

## 任务文件

- `spec.json`：固定的规则和概率表计算流程。
- `transitions.bin`、`table.json`：转移表及 SHA-256 指纹。
- `generate.ckpt`、`stage-N.vi.ckpt`：生成与值迭代检查点。
- `stage-N.values.bin`：阶段概率表；`stage-N.pending.csv`：该阶段的 36 种待出数状态成功概率。
- `events.jsonl`：计算进度事件。`*.log`：原始日志。`jobs.json` 任务索引位于应用的用户数据目录。

检查点先写临时文件再替换。转移表与任务规则、核心版本和文件指纹不一致时拒绝续算。转移表只在生成完成后才发布。

## 开发构建

Windows x64 构建机需要 Node.js、MSYS2 UCRT64。项目内放置 MSYS2 于 `.tools/msys64`，然后在 UCRT64 环境安装：

```powershell
pacman -Syu
pacman -S --needed mingw-w64-ucrt-x86_64-gcc mingw-w64-ucrt-x86_64-petsc mingw-w64-ucrt-x86_64-pkgconf
```

使用 PETSc 的 `petsc-dso` 构建，即 sequential double precision 配置。原生构建脚本会复制可执行文件依赖的 DLL：

```powershell
./desktop/scripts/build-native.ps1
cd desktop
npm install
npm run dist:win
```

安装包在 `desktop/release`。应用本身使用 Electron 30、React 18、TypeScript、electron-vite 2 和 electron-builder 24。原生求解器仍可使用原有命令行方式调用；新增参数均为可选项。

此版本没有自动更新、账号、联网计算或历史 v4 文件导入界面。


## 0.2.0：激进度

基础设置新增激进度，默认 0，范围为 0 至目标数字 / 7.5。
猝死率 = 激进度 × 7.5 / 目标数字；每个未成功出数步承担风险，成功步免除猝死，免费操作不承担风险。
此参数使策略倾向于快速成功，不保证指定平均步数。非零激进度的结果包含猝死风险，不等于原规则下的成功率。
参数在创建任务时固定，传入全部 VI/PETSc 阶段，并随任务、结果导出和检查点保存。
任务详情显示激进度和猝死率，对比页提示两任务的激进度。
旧任务自动补默认激进度 0，并使用随包保留的原版核心继续旧格式检查点；历史结果保持可查看。
新任务使用带激进度标识的新核心文件格式。
构建时同时需要上级目录原版 C++ 源码和 aggressive-version 中的新核心源码及 risk.h。

## 0.4.0：定式出口参数

新建计算新增 single / match / extend 出口预设、成功时无额外组合块、match 边界保护、六格 single 边界保护与整洁出口，以及允许所有基。

- single 固定目标占 1 格；match 默认最多 5 格；extend 默认最多 4 格，完整衔接仍需路线验证。
- 三种定式预设均要求 F 上方成功、无额外组合块；自定义目标允许调整这些约束。
- 干净出口允许残留普通块。六格 single 整洁出口要求完成物理动作后最多残留一格普通块，且数值不超过 8。
- EDGE 保护假设受保护锚点等于目标；single 的两个专用选项仅支持六格单格目标模型。
- 所有基仍遵守原奇数合成规则，且可能大幅增加状态数。最大出现数字和激进度继续独立配置。

新参数随 spec.json、结果 JSON/CSV 和转移表元数据保存；恢复时核对规则，避免混用。此版本更新原生生成器，旧核心任务保留结果但需按原参数新建计算，不能继续旧检查点。

参数回归：`node desktop/scripts/test-calculator-rules.cjs`。0.4.0 安装包位于 `release-0.4.0/Tallnum-Calculator-0.4.0-win-x64.exe`。


## 大数路线规划

在左侧选择“路线规划”，输入普通块目标与七格/十格容量。支持非标准基；所有定式都按五格声明，拒绝不足五格的原语。默认自动选择定式上限，再减少最高阶调用；也可指定 64 等上限。

点击“开始规划”后，页面显示进度、候选调用次数上界、整数动态规划下界、是否闭合证明、各阶调用分布，以及带有真实保护盘面的逐步路线。默认只显示最高阶调用，可切换查看全部步骤。最高阶是否最低和调用次数是否最少分别显示，结论限于页面记录的数值范围与 EDGE 深度。随机策略成功率和总低阶调用数最优性没有隐含认证。

结果保存到所选目录，留空则使用应用数据目录。目录中包含 `integer-result.json`（界面结果）、`binary-plan.json`（完整路线）、`ideal-connection-trace.json`（逐步盘面）、以及可复用的搜索缓存。停止计算只终止本页面拥有的规划进程，再次使用同样参数可复用完成的子任务。

本地已有依赖和构建时可双击 `start-planner.cmd` 启动当前版本，然后选择“路线规划”。首次开发构建使用 `npm run build`，运行需要系统 Python，与自动玩功能使用相同运行环境。

后端入口：`python -m automation.integer_planner 10240 --cells 10 --directory automation/runs/my-integer-plan`。程序从模型生成路线，没有内置 10240 的结果或指定拆分。10240 验证结果：最高五格 64，上界和下界均为 13。

## 十格 10240 实战路线

左侧“概率表路线规划”接受 1–255 格塔容量与 2–65535 的普通单块目标，所有目标均调用 `automation.probability_route_planner`。用户可指定任意至少五格、目标至少24的定式。程序先按最高五格目标及其主路线调用数规划，再利用真实剩余空间对执行合同做有预算的局部动态规划，核对保护块、边界、预热、残留和阶段出口；所需概率表缺失时明确报告，不自动计算或使用固定策略表替代。结果分为候选路线、搜索预算耗尽、概率表目录缺口、普通单块目标不可能、塔容量不足，以及原始发牌数字可直接取得。目录缺口不等于证明游戏中绝对无解。

十格10240的五格64上限是该低阶路线的验收约束，不是其他目标的规划限制。执行绑定保留可适用的128–40–40–40开局连接结构，并保留缓冲与真实EDGE回退；回退造成的额外调用不计入主路线调用数。五格以下或目标小于24的定式不参与规划。

页面会校验新生成路线、定式目录及执行源码的SHA-256是否与`peak13-assets/probability-validations.json`的百局记录相同，只有匹配的版本显示实测成绩。未匹配的候选路线不显示历史胜率；历史89/100包含固定策略开局，不作为新概率表路线的成绩。

输出目录包含 `route.json` 与 `planning-report.json`。开发构建若 Windows 沙箱使 Node 原生 `realpath` 返回 EPERM，可使用 `node -r ./scripts/windows-realpath-workaround.cjs ./node_modules/electron-vite/bin/electron-vite.js build`。页面的路线生成只需要系统 Python；要在另一台电脑复现概率表模拟，还需准备原始概率表及本项目的模拟运行环境。

可运行的便携版为 `release/Tallnum-probability-route-planner-portable.zip`。解压整个目录后运行 `Tallnum 计算器.exe`，在左侧打开“概率表路线规划”。启动规划时需要系统 Python 及随项目提供的 `automation` Python 模块；便携包已包含该模块和规划输入。
