# 定式入口清理

当下一定式查询返回 `out-of-model-board` 或 `out-of-model-state`，且保护区下方有残留时，执行器先搜索短操作序列，再使用原来的单次上移兼容分支。

搜索最多四个操作，每层保留二十个候选，最多访问六百个局面。候选包含连续二至五块的组合、EDGE、上移、下移和投放；整个序列最多消耗一次已知预览的投放。保护块必须全部保留，顺序不变且连续；每一步都使用完整真实盘面检查实体格数、合并、组合块限制和游戏结束。match 的 EDGE 限制同样适用于清理动作。

清理结果必须没有活动组合块，满足原定式的容量和最大允许数字，并能直接在原策略中查到动作。查到动作后，还会用真实保护区预演定式的下一个宏操作，拒绝会错误合并或分割保护区的入口。一次投放后新补充的预览尚不可见，因此对全部已解锁数字逐一检查；实际执行仍使用游戏自己的队列和 RNG。候选按清理后活动区实体格数、组合块数、投放数和操作数选择，不将其称为概率最优策略。

原局种子 `2868527136` 在第 213 阶段的入口为：

`4 / 6 / 4 / [5120 / 960 / 640 / 256 / 32]`，可见预览 `15 / 8`。

新执行器选择 `组合底部三块为14 → 上移并投放15 → EDGE合成2`，得到：

`[5120 / 960 / 640 / 256 / 32] / 2`。

保护区保留，盘面占用降为六格，定式完成后推进至第 215 阶段。完整原局前缀和修复后操作通过原始 JavaScript 引擎核对，共 3,138 个动作；该局部回归只证明原来的失败入口已被跨过，不代表整局合成10240成功。

没有修改任何定式策略文件、成功条件或转移表，因此继续使用已有 PETSc 认证。加入入口清理后的整局成功率需由完整模拟统计，不能沿用定式模型的成功率。

回归记录位于 `runs/binary10240/min24/entry-bridge-regression-004`。原100种子的整局对照位于 `runs/binary10240/min24/entry-bridge-004`，保持保存的真实开局、路线、解锁、队列及RNG，仅重新执行后续路线。每局独立保存，重启时复用完整检查点；程序异常不计为游戏死亡。大回放文件逐局写入，并由原始JavaScript引擎核对。

运行整局对照：

```powershell
python -m automation.validate_entry_bridge
```

运行已记录失败入口的局部回归：

```powershell
python -m automation.validate_entry_bridge --regression --out automation/runs/binary10240/min24/entry-bridge-regression-004
```
