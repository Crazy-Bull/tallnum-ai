# 定式胜利条件：不能残留多余组合块

从此次修改开始，新计算的五格、六格定式使用 `successNoExtraCombos=true`。

- 满足原来的目标数、目标物理格数、固定边界方向条件。
- 除选中的目标块外，盘面上下两侧都不能存在组合块。
- single 的目标必须是普通单格，因此胜利盘面不能存在任何组合块。
- match、buffer、extend 如果允许目标组合块，可以保留该目标组合块，不能保留其它组合块。
- 普通残留数字仍然允许存在；过程中仍然允许创建组合块。没有清盘或强制删块操作。

该条件参与生成器的终止判断，而非仅在策略执行末尾过滤输出。因此重新求解所得成功概率、成功和失败投放数对应新终止条件。

新计算使用独立的 `-cleanexit` 目录。模型元数据记录条件，导出标识为 `success-board-clean-v3`，查询缓存使用 `TNQUERY3`，生成断点使用 `TALLGCK3` 并检查条件是否一致。旧模型、旧缓存和旧概率保留历史语义，不能充当新条件的计算结果。计算入口的 prepare 会忽略旧条件策略。

新策略必须以至少两轮固定策略 PETSc 概率复核结尾。该概率是定式模型概率，不代表含真实残留、解锁和衔接的整局成功率。

正式五格定式重算已经启动，进度记录在 `F:/TallnumData/tallnumai-cleanexit/recalculation.json`；配置包括从旧表恢复的来源目录、独立目标参数及逐项完成/失败状态。第一批汇总了 768、640 两个已有库中的14种五格目标/出口/跨度组合；另有补算脚本扫描全部运行目录的目录清单，纳入剩余组合。旧表里成功终止的行会重新展开；其它转移行直接复用。失败或中断时可查看进度文件及每个生成器的断点。

六格32、40、48的单格定式保持独立计算流程，新增计算也会读其旧表并重新展开旧成功终点。新库登记为共享可发现来源，路线的 prepare、计划、验证和游玩入口只读取符合新条件的策略。五格和六格都分开存放新表、策略和 PETSc 结果，旧库不会被覆盖。

验证：`automation/tests/clean_exit_model.cpp` 检查普通目标、组合目标、边界上下残留和旧语义；`test_clean_exit.py` 检查生成器默认条件、断点拒绝条件变更和模型配置；`validate_clean_exit.py` 在三格目标24、上限48的小模型上证明增量复用结果与全新生成图概率一致，并检查导出、完整/缓存查询一致性及两轮 PETSc。结果保存在 `automation/runs/clean-exit-validation/validation.json`，该小模型不加入正式定式库。
