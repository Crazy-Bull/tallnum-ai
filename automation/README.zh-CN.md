# Tallnum 五格定式组合与自动玩

通用概率表规划器现在按最高五格目标、该目标的主路线调用次数、全部定式调用次数依次优化。它按可用格数、数值和出口复用构造子问题，补全非标准基的倍数，并将每个复用的构造重新放入完整保护盘面核验。其他规格的定式仍由允许列表决定，不受五格 64 的通用上限限制。带边界和预热块的定式按相应契约绑定；预热块必须先真实构造、再释放为定式的活动块。

执行绑定会核对真实剩余空间、允许列表、边界及出口；在不增加最高阶五格调用的情况下，优先使用可接入且严格限制残留的较大工作区single，并明确验证真实等值连接。对仍有至少六格工作区的较大标准目标，程序以有预算的局部动态规划求解等价合同，优先使用严格小残留的较大工作区定式，最多替换为八个阶段；每次替换必须保持完整入口和出口一致。非标准预热链保持原契约，允许列表未授权的定式不参与替换。`executionExpansions`记录替换范围，规划报告列出替换次数；这类有限搜索和执行连接不代表完整路线最少总调用的证明。

十格大目标的较大首段single，在允许列表同时包含严格六格32、40和该首段目标的生产定式时，可接入128、三次六格40、EDGE24、首段single的开局结构。当前目录覆盖40、48入口，全程使用现有概率表；释放保护身份不删除实际24。缺少任一允许生产定式时不添加该开局。缓冲救援按待消除锚块登记异值同头buffer；single、match、extend均可在真实EDGE只消除末端锚块且完整保留前缀合同的条件下回退重建。回退额外调用不计入主路线调用数，但实测逐局记录实际调用。指定允许列表时不自动添加未允许的救援定式；验证器保留规划器的救援配置。

执行计划中的EDGE前，还会预测完整真实盘面；若残留参与连锁导致出口不符，只接受能够保留全部保护块和顺序、且随后EDGE恰好达到原出口的一次正常轮转。轮转消耗真实可见待出数，容量不足或无法恢复合同则拒绝；逐局结果的`connectionAlignments`记录这些操作。它不改写盘面、不调整发牌、不把残留算成已完成的定式。

已有结构候选可用 `python -m automation.probability_route_execution --route <原候选路线> --catalog <概率表目录> --out <新目录>` 重新绑定，保持旧成果不变，仍需独立实测。历史89/100版本含固定策略开局，其结果不能作为全程概率表修复版的胜率。

运行示例：`python -m automation.probability_route_planner 10240 --cells 10 --catalog desktop/peak13-assets/probability-catalog.json --out automation/runs/my-route --node-limit 100000`。`planning-report.json` 记录最高五格目标、调用计数、完整阶段数及有预算的最优性状态。预算暂停不能解释为无解；候选结构通过也不表示随机胜率已经验证。新路线测试入口为 `python -m automation.probability_route_validate --route automation/runs/my-route/route.json --catalog desktop/peak13-assets/probability-catalog.json --out automation/runs/my-route/validation-100 --attempts 100`，从新游戏开始，只使用待出数概率表，保留回退，并用固定原游戏引擎核对回放。回退额外调用不计入规划主路线次数。

最新结果：全部使用五格定式，五格 64 最少调用 **13 次**，已在记录的有限合成模型内闭合上下界证明。旧 16 次候选保留作比较。见 [完整路线与证明](runs/binary10240/minimum64/README.zh-CN.md)。




大数路线默认按最高阶定式及各阶调用次数选择，支持非标准基中间块与目标，见 [低阶定式路线规划器](LOW_ORDER_ROUTES.zh-CN.md)。
10240 的新路线最高使用五格 64，完全避开 80，并通过原版引擎的指定出数重放。

以下为旧版残局难度加权规划器及自动玩入口的说明。
当前七格任意目标的可复用程序接口见 [七格搜索程序](SEVEN_ROUTES.zh-CN.md)。
从原始动作寻找非标准基的最短结构路径，见 [非标准基合成程序](NONSTANDARD_BASE.zh-CN.md)。
按最新“最小化路线最大数字”的标准预计算全部偶数，见 [全偶数预计算](EVEN_PRECOMPUTE.zh-CN.md)。
使用、补算、续算和模拟验证见 [路线规划器 v2](ROUTE_PLANNER.zh-CN.md)。
待出数状态期望概率的压缩、运行时搜索和五格实验见 [期望概率方案](PENDING_VALUES.zh-CN.md)。
下文的旧版七格自动玩继续使用原入口；新版规划结果尚不接入网页自动玩。

默认目标为 Standard 七格小塔的普通单格 **768**。七格按等值二分；六格补齐任务使用 `T=a+a+b` 中 `|a-b|` 最小的唯一合法配对，先把两份 a 合并成单格，再用最多四格的 b 与它一起 Group。小于 48 的子目标使用对应五格定式。六格需要独立普通块时采用等值二分；有合法三分的补齐任务不另行补算昂贵的二分候选。

## 启动

本次新增的自动化功能需要 Windows x64、Python 3.11+、Google Chrome，以及 `requirements.txt` 中的 Python 包。原有桌面计算功能仍使用随包原生核心，不依赖 Python。

实时操作默认连接已经打开的 Chrome 游戏标签页，保留登录和盘面，不新建游戏标签页。首次连接前在 chrome://inspect/#remote-debugging 启用远程调试，并允许 Chrome 的连接提示。停止时只断开控制连接，不关闭用户浏览器。命令行可用 `--browser msedge` 切换到 Microsoft Edge。

```powershell
python -m pip install -r automation/requirements.txt
./automation/build.ps1
python -m automation plan --directory automation/runs/<run-directory>
python -m automation prepare --directory automation/runs/<run-directory>
python -m automation validate --directory automation/runs/<run-directory>
```

`<run-directory>` 表示现存运行目录。旧 640、768 策略目录已删除，不能再将其用于 `--directory`。历史迁移记录见 [定式存储位置](../maintenance/TEMPLATE_STORAGE.zh-CN.md)。

验证默认比较模型排序前 20 条路线，每条 100 次，另做独立验证。
降低计算预算时可加 `--candidate-limit 1 --attempts 100`，只检查模型最优候选；
这不能证明它在真实游戏中的表现优于其他候选，结果会记录实际比较范围和样本数。

`prepare` 会对基础策略做 PETSc 收尾，并为 128 的 `match`、`extend` 出口分别补算激进度 `0.05`、`0.01`、`0.005`、`0.001`。单独重跑变体可执行 `python -m automation.aggressive --directory automation/runs/<run-directory>`；已完成的 PETSc 阶段会跳过。之后执行 `python -m automation.certify --directory automation/runs/<run-directory>` 将零风险结果绑定到策略目录，再重新执行 `plan` 和 `validate`。

也可以构建并启动 `desktop`，进入新增的「自动玩」页。先选择数据目录，再依次检查、补算、验证。模拟通过后可连接当前游戏标签页，点击连续运行或单步；窗口初始处于暂停状态。

命令行启动实战：

```powershell
python -m automation play --directory automation/runs/<run-directory>
```

通过数据目录的 `control.json` 控制实战：`{"mode":"run"}` 连续运行，`{"mode":"paused"}` 暂停，`{"mode":"step","token":1}` 单步（每次使用新 token），`{"mode":"stop"}` 停止。桌面会原子写入该文件。暂停在一个真实输入完成后生效。

连接现有 Chrome 时保留原窗口尺寸，页面使用实际窗口尺寸，可调整大小和滚动。键盘输入前清除网页控件焦点；Group 选区可见时保持视口不动，仅在超出窗口时做最小必要滚动并重新读取坐标。释放鼠标前检查选区及合并就绪标记；选区错误时取消拖动，盘面未变时最多重试一次。窗口过小、输入未确认或读取暂时失败时保留浏览器并暂停，保存待确认操作。点击“连续运行”后先读取实际盘面：已经执行的操作只确认一次；盘面完全未变化时才重发；出现其他变化时保持暂停。

开局使用普通单格 24 定式（maxGoalCells=1），组合块 24 可以是中间状态，不能作为这一阶段的成功出口。开局没有实体固定块 F，但仍须保留与定式一致的虚拟 F 位置；每个匹配的宏动作结束后跟随其 fpos，而不是强制归零。额外真实合并使投影不再对应时才回到空边界查询。开局回归文件 opening-before-fix.json 和 opening-after-fix.json 使用同一批 100 个种子；结果只表示这批样本。

更新进程后，若当前局的完整操作记录存在，可使用 `python -m automation play --directory automation/runs/<run-directory> --resume-current-game` 恢复原路线阶段。系统重放已确认的观察记录、兼容旧版开局边界规则，并核对当前盘面；不相符时保留盘面并停止。每个新动作记录 openingBoundaryVersion 和 stageBefore，便于诊断阶段出口。

使用项目内依赖时可安装到 `automation/.deps`；CLI 会自动加载该目录。发布包不会打包该本机依赖目录，仍需安装 Python 依赖。

## 计算与文件

- `catalog.json` / 每个定式 JSON：固定策略指纹、入口模型、成功率、条件步数、残差、不终止概率和 PETSc 核对结果。规划只读取通过 PETSc 核对的策略。
- `*.graph.bin`：从 36 个入口可达的固定策略图；终止成本由原生操作展开确定。
- `*.policy.bin`：转换后的固定策略；激进度只影响来源策略，统计不加人工猝死。
- `*.policy.query.bin/json`：首次使用时生成的紧凑查询缓存，绑定策略和转移表 SHA-256；运行时无需加载全动作转移图。
- `generated/edge-规则指纹/5-T-S/`：缺失的目标 T、最终占格上限 S 的五格转移表和值函数。默认最多 5000 轮 VI；这是可执行策略，不代表最优策略。
- `plan.json`：非支配路线、唯一三分配对及缺失参数。入口、出口相容才串联。
- `validation.json`：至多前 20 条路线的真实规则模拟、重新排序和独立留出验证。默认每条 10000 局；存在不匹配或未结束样本时不发布有限总期望值。
- `session.json`、`actions.jsonl`、`result.json`：实战路线身份、逐步前后盘面、跨重试出数与结果；异常保存 `incident.json/png`。

有完整值函数但没有策略的文件，可导出确定性贪心策略；汇总 JSON 不能代替策略。导入转移表时必须有同名 `TABLE.rules.json`，记录当前 `tallnum_reachable.cpp` 的 `ruleSha256` 和表的 `tableSha256`。旧规则生成的表和策略不会参与规划，需重新生成。历史 TALLVAL4 没有内嵌转移表指纹，首次导入只能检查状态数和参数来源；之后使用表、输入文件、导出策略的 SHA-256 绑定。带身份的固定策略还会验证内部转移指纹。

自定义导入：

```powershell
python -m automation import --directory automation/runs/<run-directory> --table TABLE --source POLICY_OR_VALUES --exit match
```

出口为 `single`（普通单格，需上限 1）、`match`（补齐相邻同值块）、`extend`（可扩展成功步，需上限 ≤4）。同一数值的三种出口不能混用。

基础策略经过两轮 PETSc 策略改进与一轮零人为风险固定策略评估；激进策略经过五轮 PETSc 激进目标策略改进，再以零人为风险进行最后一轮评估。只有 PETSc 明确收敛，并且其成功率与独立固定图计算相差不超过 `1e-5` 的策略才进入规划。统计器对固定图建立稀疏吸收方程，求成功/失败/不终止概率及带条件的一阶成本矩。复用原 C++ 模型与回放展开；Python 使用 SciPy 稀疏求解，BiCGSTAB 失败时回退 LGMRES。检测闭合非终止 SCC；存在可达无限循环的策略不进入有限期望 DP。

三指标组合使用独立、36 种预览等权的入口近似。最终总期望为 `(u+v)/p`，不会平均各子任务的条件均值，也不只保留局部最小比值。结果是限定模板与固定策略库内的候选，非全局最优证明。

## 真实游戏适配约定

实战读 IndexedDB 存档，同时核对 DOM 盘面、投放数及动画锁；只将两项可见预览传给策略。通过正常键鼠事件投放、轮转、Edge 和 Group，不修改游戏状态或 RNG。

真实开局没有实体固定段 F：首段保留宏动作的虚拟边界位置重新查询策略，单块轮转映射为投放，额外自动合并按真实规则接受并重新查表。后续阶段只保护固定段及新生成目标，剩余活动块保留到下一阶段。若入口只剩 F 下方的活动块而不在表内，先执行一次合法向上轮转对齐，再查表；该投放成本进入模拟与实战统计。

网页和当前定式模型的 Edge 都在每次合并后重新去个位：`10/15/24 → 2/24`，`240/244/40 → 8`。执行器仍逐步比较实际盘面与网页规则预测；若宏动作的后续盘面不同，就丢弃该宏动作剩余步骤并重新查询。三指标仍含五格入口独立近似，不能直接当作网页实战成功率。

模型判定成功的轮转仍会在网页中投放，模拟器按网页行为执行。定式死亡、容量用尽、不支持的成功出口及不在固定策略入口域的局面，属于预先规定的路线放弃；识别/输入/模型异常则暂停留档，不重复发送不确定输入。

路线被放弃后不立即重开：执行器改为连续普通投放，直到真实网页显示“数字塔已满”。收尾投放计入失败成本，模拟使用同样的处理。连续运行时结算面板至少停留 10 秒，然后将本局记录追加并落盘到 `rounds.jsonl`，再点击面板的“再来一局”。暂停和停止控制会阻止自动重开。`game-over.json` 保存最新的结束盘面与记录。

若要保留上次浏览器中尚未结束的盘面并将它投放至结束，可使用 `python -m automation play --directory automation/runs/<run-directory> --finish-current-game`。它不会恢复原路线阶段，而是直接完成当前局，再按 10 秒结算流程开启正常新局。

每行记录对应一局真实游戏：`success` 表示本局是否曾实际达到目标普通块，`dropsToTarget` 是首次达标的投放数（失败为 null），`drops` 是最终游戏结束时网页显示的投放数。还记录时间、目标、最终盘面、结束原因和唯一 roundId。连续重开追加记录，不覆盖历史；从已有存档接续的局标记 `partialStart`。

达到 768 后继续游玩：只在策略的影子盘面中将底层 768 按 384 处理，保护它并复用原路线的六格 384 后半段。每个输入仍独立核对真实网页规则，网页数字和存档不被修改。虚拟终点的 384 合并可能在真实盘面中留下 Group，不能假定它与实际 768 自动相等合并；这时安全转为普通投放至结束，避免用失去对应关系的虚拟坐标操作。整局仍记录为已成功达到原目标。

路线验证的成功条件步数仍截至第一次实际达标；实战日志另记录达标后继续游玩至结算的最终投放数，两者不能混用。

真实规则参考 `vendor/tallnum.mjs`，取自 `https://pku2048.cn/game/tallnum.js?v=20260922-tallnum-small-all-unlocked`，SHA-256 `67601620b932b4389ee266d88d1104c0b896d6474633b9fb8c22eeb80697a271`。模拟器为 Standard 七格 poolVersion 2 的端口。网页版本变化后应重新做一致性验证。

默认缓存约 2 GiB 估算量的原生策略进程，以避免每局反复加载小定式；可通过 `TALLNUM_POLICY_CACHE_MB` 调整。大目标补算和完整验证可能需要较长时间；停止后已发布的统计与结果可复用。

## 中间数值上限

计算器的“最大出现数字”独立于目标数字，留空时沿用目标作为上限。
例如目标 16、上限 32 时，中间可以保留 24 或 32，再通过 EDGE 操作降位；成功条件仍为 16。
命令行生成器支持 `--max-value 32`。上限必须不小于目标，且不超过 65535。
自动路线准备对小于 48 的叶定式补算上限为 max(48, 2×目标) 的版本；缺少这一上限时先补算，不回退到更小的上限。
每份新转移表的 `.model.json` 记录上限，检查点及查询缓存也校验该参数。
扩大上限会增加状态空间，已有原上限定式的统计不会被冒充为扩大后的结果。

新版计算器会为转移表保存规则和上限校验文件，五格结果可导入自动化目录。
导入最后一份 PETSc 策略时，可同时用 `--petsc-result` 指定任务中的 `final-actual.json`，
并用 `--petsc-rounds` 记录已执行的 PETSc 轮数（至少两轮）；导入还会按实际出口条件做 PETSc 复核。

## 成功出口修复

投放或轮转达到目标时，底层模型保留终止盘面，供扩展出口检查与动作编译使用。入口已经含有紧邻固定段的普通目标块时，执行器先识别合法扩展出口，避免因枚举器未保存终止盘面而放弃。

自动路线对小于 48 的目标，在已具备扩大上限的策略时，统一使用上限为 max(48, 2×目标) 的 single、match、extend 版本，避免上一段残留数字超过下一段的上限。

策略清单使用 exitSemantics=success-board-v2 区分修复前的出口统计；只有按新出口规则导出策略图、并通过两轮 PETSc 出口概率评估的策略可用于自动路线。原有策略计算中的 PETSc 改进轮次另行保留；这两轮直接评估最终固定策略图，第二轮使用更严格的误差阈值。PETSc 概率对应五格模型及其入口分布；实际七格路线另做整局模拟验证。

升级已有目录时先停止实战进程，运行 `python -m automation.refresh_exits --directory automation/runs/<run-directory>`，再重新 plan 和 validate。旧清单备份为 catalog-before-success-board-v2.json。当前局有完整记录且升级后的路线与已执行操作一致时，可用 --resume-current-game 恢复。边界对齐轮转若恰好完成相邻等值合并，应作为 match 出口推进阶段，不能因固定块 ID 改变而放弃。


## 已删除的旧策略库

旧 640、768 策略目录及其专用实战说明已删除。请将示例中的 `<run-directory>` 换成 `automation/runs/` 下实际存在的运行目录。

## 非标准基的显式构造

新版搜索不再把 14、26、54 等非标准基普通块作为独立 single/match 五格任务。候选必须从标准基 single 开始，将每次配对块构造列为五格 buffer，并显式列出 EDGE；等值配对可通过 buffer 与既有锚点自动合并倍增。每段分别登记生成器参数、五格成功率及成功/失败投放矩，完整路线按全部阶段合成成本。

buffer 的目标可以是普通块或最多四格的组合块，普通中间数只允许标准基 1、3、5、15。它紧邻受保护锚点，完成后立即执行列出的 EDGE，或在等值时直接合并。结构状态中的四格是上限；运行时核对真实值、占格和相邻关系，保留实际残留盘面。

配对值会比较同一个十位桶中不同目标的 buffer 成本，不假定它们可达。缺少策略时由五格生成器补算，并完成 PETSc 固定策略出口评估；不可达或无有限期望的策略不参与选拔。结构缓存已升级，旧的隐式非标准目标候选不会用于新版验证。

例如 26 的显式依赖链会经过 176 和目标为 170 的 buffer。因此五格目标上限为 128 时，这条链被排除，不能继续以一个“26 定式”的低结构成本参加 640 排名。提高上限后仍需逐段生成与整局模拟，显式拆解本身不证明可执行。
